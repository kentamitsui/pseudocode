# スタックとキューを日本語擬似コードで学ぶ実践問題集：データ構造の「動き」をマスターする

## 1. はじめに：なぜ優れたプログラマは「データ構造（ADTs）」を語るのか

「計算機が存在するやいなや、それは科学の進むべき道を導くことになるだろう。どのような結果を求めるにせよ、『いかにすれば最短時間で計算結果に到達できるか？』という問いが常に立ちはだかるのだ」

これは、1864年にチャールズ・バベッジが遺した言葉です。また、1843年に世界初のアルゴリズム（ベルヌーイ数を求める計算）を記したエイダ・ラブレスも、抽象的な論理を「機械の動き」へと翻訳する重要性を理解していました。

現代のプログラミングにおいても、この「最短時間で結果を出す」ための鍵は、洗練されたコード（書き方）よりも、その背後にあるデータ構造にあります。プリンストン大学のRobert Sedgewick教授は、データ構造を学ぶことは、単なる知識ではなくアルゴリズムの性能を制御するための「語彙（ボキャブラリー）」を増やすことだと説いています。

本ワークブックでは、すべてのデータ構造の第一原理である「スタック」と「キュー」を、論理的な思考ステップを経てマスターします。Alan Turingが1947年に述べたように、計算プロセスの「仕事量」を測る視点を養いましょう。

### 核心的概念の対比：LIFO vs FIFO

| 項目           | スタック (Stack)               | キュー (Queue)                     |
| -------------- | ------------------------------ | ---------------------------------- |
| 概念           | LIFO (Last-In, First-Out)      | FIFO (First-In, First-Out)         |
| 動作の別名     | 後入れ先出し                   | 先入れ先出し                       |
| 主な操作       | Push（積む） / Pop（取り出す） | Enqueue（追加） / Dequeue（削除）  |
| 現実の例       | 重ねられたお皿、ブラウザの履歴 | アトラクションの行列、プリント待ち |
| 重要キーワード | 逆転、最新情報の優先           | 公平性、順序の維持                 |

## 4. 第1問：スタックの基本操作（お皿洗いのLIFOシミュレーション）

スタックは「お皿の山」です。一番上に新しい皿を置き（Push）、洗うときも一番上から取ります（Pop）。

**【建築家の視点：メモリの厳密性】** スタックに要素を追加する際、現代の64ビットマシンでは、各要素への参照（ポインタ）だけで8バイトのメモリを消費します。さらに、Java等のオブジェクト指向環境では、オブジェクトごとに16バイトのオーバーヘッドが発生します。データを積み重ねることは、単なる論理作業ではなく、物理的なリソースを積み上げることでもあるのです。

## 6. まとめ：データ構造という「プログラマの語彙」を増やすことの大切さ

Robert Sedgewick教授が説くように、データ構造の理解は「性能の科学」です。

64ビットポインタ（8バイト）がメモリのどこを指し、16バイトのオブジェクトオーバーヘッドがどれほど積み重なるかを意識できるプログラマは、システムの限界を予測できます。LIFOとFIFOは、将来学ぶ「木（Trees）」や「グラフ（Graphs）」、あるいはディープニューラルネットワークの複雑なデータフローを解き明かすための、最も純粋な第一原理です。
